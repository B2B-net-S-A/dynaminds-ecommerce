# Native order split (222), 23.10.2026

Owner-approved variant A: a native process without triggers on core tables. One split creates exactly one
child order (Base `addOrderBySplit` semantics: "Creates a new order by splitting selected products from an
existing order"); 1→N is repeated calls, each its own transaction. Local acceptance only; no Base
account/sandbox request was made. The older Source210 split (`order-split-*.ts`, `order_split210_*`) is
untouched and stays unmounted unless its own construction check passes.

## Schema (migration `server/222_order_split.sql`, registered in `db.ts` after 221)
Own tables only, tenant RLS policy `tenant_scope` (USING + WITH CHECK), `SELECT, INSERT` for `dyna_app`,
append-only guard `order_split222_immutable()` (no UPDATE/DELETE/TRUNCATE) attached only to them. No
trigger, column, constraint or foreign key on any core table.

| table | content |
|---|---|
| `order_split222_previews` | validated plan: request + hash, parent snapshot (header, items, picks, reservations, locations), plan (lines, physical units, shipping, totals), `parent_total_after + child_total = parent_total_before` (CHECK), expires after 15 min |
| `order_split222_executions` | one per preview (`UNIQUE(tenant_id,preview_id)`), child order, before/after snapshot, same total CHECK |
| `order_split222_targets` | lineage: parent item → child item, moved quantity and value, parent quantity/value after |

Packaging: resource chain after 221 (`6d121d4`). Cold inspection: exact compiled 222→221 inverse,
chained before 221 with strict marker parity (`9f00c2a`). All nine guards are true before and after 222.

## Process (`server/order-split222.ts`)
1. **Preview** (one transaction): current role/key check, per-order advisory lock, idempotent by
   `(tenant, client_key)` + request hash (same key, other body → 409). Locks the warehouse policy, then
   the parent order and its items, picks, reservations and locations (`FOR UPDATE`), checks the refusals
   (below) and computes the plan. Writes only the preview row.
2. **Execute** (one transaction): idempotent by its own client key (replay → the same execution and
   child, 200). Requires the preview's actor/key, `scope_hash`, not expired, not executed. Re-captures
   the parent; any change of header/version, items, picks, reservations or locations → 409 (new preview).
   Re-checks every refusal. Then:
   - child header = the full parent header (all `orders` columns) with a new id, number
     `<parent>-S<n>`, portal token, `source='order_split'`, `channel_id/external_id/source_snapshot`
     NULL, version 1, and its own `total` / `shipping_cost`;
   - child `order_items` (new ids), `order_pick_items`, `reservations` (state `active`) and
     `reservation_locations` (the child takes the first units in location order; a fully taken location
     row is re-assigned to the child — location rows are never deleted);
   - parent quantities/values reduced; fully moved lines, picks and reservations removed;
   - `stock.reserved` unchanged (the reservation moves between orders); committed rows are reconciled
     exactly (totals, shipping, line sums, per product reservation = location = pick sum) or 500;
   - `base_wire220_allocate_pending('order')`, execution + targets rows, `order.split` (parent) and
     `order.created` (child, `split_from`) local events (no automations/outbox), audit;
   - child buyer address: the inherited order address, read through the createOrder installation proof
     (`prepareCreatedOrderBuyerInstallationInTx` + `effectiveDeliveryForCreatedOrderInTx`); the
     buyer-address sidecar is not copied (an order with a sidecar is refused).

### Money (grosze, exact)
- A line with `line_total = price × quantity` moves `price × moved`; any other line moves
  `floor(line_total × moved / quantity)` and the remainder stays with the parent.
- `shipping_cost_to_child` (default 0, ≤ parent shipping) moves from parent to child.
- `parent_total_after = parent_total − child_total`, `child_total = moved line totals + moved shipping`.
- Bundles: physical units follow the frozen `components` recipe of each moved line.

### Refusals (no effect)
| status | case |
|---|---|
| 409 | status other than `new`/`paid`; replacement order; WMS lots enabled for the company; any payment (`payment_entries`, payment imports); documents (invoices, proformas, local invoices, credits, …); parcel plan, shipments, shipping/label plans; picking waves, packing, scans (`scanned>0` on items/picks/locations), stock movements, WMS rows; merge claims/origins/executions; returns, exchanges; external intents/fulfilment plans, B2B/dropship orders; buyer-address sidecar (`buyer_address_state`/receipts); non-active, consumed or released reservation/location; reservation ≠ picks or not fully located |
| 422 | quantity above the line, parent would keep no line, shipping above the parent's, duplicate/empty items, child value above the order value |
| 404 | line not in the order; order not visible in the company (foreign tenant) |
| 403 / 401 | viewer or missing scopes; API key revoked/expired or a credential other than the authenticated key |
| 503 | copy without the 222 schema |

Tables that `dyna_app` cannot read are not queried; each is covered by a readable parent fact above.

## Access
- Roles admin/operator write, viewer reads.
- API keys (the `/api/v1` aliases): `orders:read`, `inventory:read` and for writes `orders:write`,
  `inventory:write`. Credential custody: the route keeps only the SHA-256 of the presented key; inside the
  transaction `buyer_address_identity` re-checks the hash, validity, unchanged role and MFA policy and
  `order_merge_key_grant` the current scopes (writes pin membership and key rows).

## Routes (`server/order-split222-routes.ts`, always registered; 503 without 222)
| method | path | body / result |
|---|---|---|
| POST | `/api/orders/:id/splits/previews` | `{client_key, items:[{item_id, quantity}], shipping_cost_to_child?}` → 201 new / 200 replay, `{preview:{id, scope_hash, parent_total_before/after, child_total, child_shipping_cost, parent_shipping_cost_after, currency, lines[], physical[], expires_at}}` |
| POST | `/api/order-splits/:id/execute` (`:id` = preview) | `{client_key, scope_hash}` → 201 / 200 replay, `{execution:{id, preview_id, parent_order_id, child_order_id, child_number, totals, targets[]}}` |
| GET | `/api/order-splits/previews/:id` | preview + `execution_id` (or null) |
| GET | `/api/order-splits/executions/:id` | execution with targets |
| GET | `/api/orders/:id/splits` | `{children:[execution…], origin: execution|null}` |

Every response carries `available`, `current_role`, `can_split`, `read_only`. Health:
`order_split222_available` (true only with the 222 schema). LOCAL: the existing `order_splits_available`
flag keeps describing Source210 — the current web split panel and the Source210 wiring test read it, and
setting it from 222 would send that panel to unmounted Source210 routes.

## Base `addOrderBySplit`
See `BASE-WIRE-ORDERS220-20261023.md` (§ addOrderBySplit): derived `order_product_id`, gross
`delivery_cost_to_split`, `new_order_id`, Idempotency-Key → native step keys.

## Not copied / not modelled (LOCAL)
Order field values, payments, documents and history are not copied to the child; the child has no
channel/external identity; the Base journal (221) shows the child's `order.created` as log type 1, the
parent's `order.split` is not mapped to a Base log type.
